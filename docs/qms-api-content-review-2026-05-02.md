# مراجعة محتوى نظام الجودة عبر API

**التاريخ:** 2026-05-02  
**النطاق:** قراءة API للنظام المنشور `quality.aqiltech.sa` مع مقارنة سريعة بمحتوى النظام المحلي.  
**ملاحظة أمنية:** لم يتم تنفيذ أي تعديل أو حذف أو اعتماد أو نشر. لم يتم توثيق كلمات مرور أو رموز جلسات في هذا التقرير.

## 3. فجوات التخطيط والمحاور

- جميع الأهداف الاستراتيجية الثمانية نشطة ومرتبطة بمحاور.
- جميع الأهداف التشغيلية لها مالك.
- جميع الأنشطة التشغيلية لها مالك أو مسؤول.
- جميع المؤشرات مرتبطة بأهداف تشغيلية ولها مالك `ownerId`.
- جميع الأهداف الاستراتيجية الثمانية تفتقد حقول KPI/ baseline/ target على مستوى الهدف الاستراتيجي نفسه، رغم وجود مؤشرات تشغيلية مرتبطة.
- 16 هدفًا تشغيليًا لا يحتوي على `currentValue`.
- 16 مؤشرًا لا يحتوي على مسؤول إدخال بيانات `dataEntryUserId`، وهذا لا يعني غياب مالك المؤشر.
- 16 مؤشرًا لا يحتوي على معتمد قراءة `approverUserId`.
- مبادرتان لا تحتويان على إدارة ولا تواريخ بداية/نهاية.

أمثلة المبادرات الناقصة:

- `INI-2026-033` مسار الحصول على شهادة ISO 9001:2015 خلال 2026.
- `INI-2026-032` تشغيل منظومة قياس تجربة المستفيد عبر QMS.

## 4. فجوات المخاطر

- جميع المخاطر الـ 14 في حالة workflow `DRAFT`.
- 11 خطرًا بلا تاريخ مراجعة.
- 6 مخاطر عالية أو حرجة ما زالت في المسودة.

أعلى المخاطر:

- `RSK-2026-002` جودة بيانات ضعيفة تؤدي إلى قرارات خاطئة، score=20.
- `RSK-2026-001` اعتماد مفرط على مصدر تبرع رئيسي، score=20.
- `RSK-2026-003` تشدد ZATCA والمركز الوطني في الرقابة، score=16.
- `RSK-2026-004` فقدان قيادات مفصلية بدون خطة تعاقب، score=15.
- `RSK-2026-005` فشل التحول من الرعاية إلى التمكين، score=15.
- `RSK-2026-013` انقضاء صلاحية الرخص والتراخيص دون تجديد، score=15.

## 5. الوثائق والمحتوى

وحدة الوثائق في النظام المنشور لا تعرض وثائق عبر `GET /api/documents`، بينما توجد سياسة جودة نشطة عبر `GET /api/quality-policy`.

البوابة العامة عبر `GET /api/public/portal` ترجع:

- `portalEnabled: false`
- سياسة جودة عامة معتمدة إصدار `1.0`
- لا توجد إعلانات عامة
- لا توجد وثائق عامة
- لا توجد استبيانات عامة

تم اعتماد أن البوابة العامة خارج نطاق النشر، وأن النشر العام سيكون عبر الموقع الرسمي للجمعية. لذلك لا توجد توصية بتفعيل `portalEnabled`، ويقتصر دور النظام على إدارة الوثائق داخليًا وتجهيز النسخ العامة التي ستُنشر في الموقع الرسمي.

هذا يعني أن أرشيف وثائق ISO المحلي الغني لم ينعكس بعد في وحدة الوثائق الحية أو لم يتم نشره/ربطه داخليًا. بعد مطابقة مجلد `ISO9001` ظهر أن 92 عنصرًا صالحًا موجودة محليًا بعد استبعاد ملفات Word المؤقتة، منها 89 غير ظاهرة كسجلات وثائق في API، و3 تطابقت كسجل سياسة جودة فقط.

## 6. خلل API مكتشف

Endpoint:

```text
GET /api/reports/iso-audit
```

يرجع خطأ 500 بسبب أن التقرير يحاول قراءة الحقل `value` من نموذج `KpiEntry`، بينما الحقل المتاح في Prisma هو `actualValue`.

الأثر:

- تقرير ISO التحليلي لا يعمل.
- قد تتعطل لوحة التقارير أو التصدير إذا كانت تعتمد على نفس المسار.

الإصلاح المقترح:

- تعديل select في تقرير ISO من `value` إلى `actualValue`.
- مراجعة أي استخدام مشابه في تقارير KPI القديمة.

## 7. أولوية العمل المقترحة

1. نشر وثائق الجودة الأساسية في وحدة الوثائق وربط الإصدارات.
2. إنشاء تدقيق داخلي واحد على الأقل مع نتائج وإجراءات.
3. إنشاء مراجعة إدارة واحدة مكتملة مع المدخلات والمخرجات.
4. تحويل المخاطر من DRAFT إلى مسار اعتماد فعلي، خصوصًا المخاطر العالية.
5. تعيين مسؤول إدخال ومعتمد لكل مؤشر.
6. تعبئة القراءات الحالية للأهداف التشغيلية.
7. إنشاء مصفوفة الكفاءات وخطة التدريب.
8. إنشاء خطة اتصال موثقة.
9. إصلاح `GET /api/reports/iso-audit`.
10. تجهيز حزمة الوثائق العامة التي ستُنشر في الموقع الرسمي للجمعية، مع عدم تفعيل بوابة النظام العامة.
