# سياسة نقل الملكية عند تغيير الموظفين
**جزء من إجراء الموارد البشرية HR-001-2026** | الإصدار 1.1 | 2026-05-02

> هذه الوثيقة تستكمل إجراء HR-001-2026 ببند تشغيلي يحمي **استدامة المؤشرات والمسؤوليات** عند تغيُّر الموظفين.

---

## 1. الإطار العام

كل موظف في جمعية البر الخيرية بصبيا قد يكون **مالكاً رسمياً** في نظام إدارة الجودة (QMS) لأحد العناصر التالية:

- 🎯 أهداف استراتيجية (`StrategicGoal.ownerUserId`)
- 🚀 مبادرات (`Initiative.ownerId`)
- 📊 مؤشرات أداء (`Indicator.ownerId`)
- 📋 أنشطة تشغيلية (`OperationalActivity.ownerId`)
- ✅ مهام متابعة (`FollowUpTask.ownerId`)

عند مغادرة الموظف أو تغيُّر دوره، **يجب نقل هذه الملكيات بشكل رسمي وموثَّق** قبل تعطيل حسابه — تطبيقاً لمتطلب **ISO 9001:2015 §5.3** (الأدوار والمسؤوليات).

---

## 2. متى يُطبَّق هذا الإجراء

| الحالة | الإجراء |
|------|------|
| استقالة موظف | إلزامي قبل تسليم العمل |
| إنهاء خدمة | إلزامي قبل تعطيل الحساب |
| تغيير قسم/منصب | إلزامي خلال 7 أيام |
| إجازة طويلة (>30 يوم) | تعيين مالك بديل مؤقت |
| تغيير اسم الموظف (زواج/تعديل) | لا يُطبَّق — تحديث ملف فقط |

---

## 3. خطوات نقل الملكية (الإجراء الإلزامي)

### خطوة 1️⃣ — تشخيص ما يملكه الموظف

قبل بدء الإجراء، يُنفَّذ تقرير "ملكيات الموظف" من النظام:

```
GET /api/users/[id]/ownership-summary
```

أو من لوحة المتابعة المؤسسية: قسم "ملكيات الموظفين".

ينتج تقرير تفصيلي بكل ما يملكه الموظف.

### خطوة 2️⃣ — تحديد المالك البديل

يحدد المدير التنفيذي بالتشاور مع مدير الجودة المالك الجديد:

| النوع | معايير اختيار البديل |
|----|------------------|
| هدف استراتيجي | مدير قسم أو منصب قيادي مُسنَدة إليه نفس المسؤولية |
| مبادرة | مدير القسم المسؤول عن التنفيذ |
| مؤشر أداء | مَن يقوم بإدخال البيانات أو يستفيد منها مباشرة |
| نشاط تشغيلي | مدير القسم المسؤول وظيفياً |
| مهمة متابعة | الشخص الموكَل إليه فعلياً |

### خطوة 3️⃣ — تنفيذ النقل في النظام

يقوم مدير الجودة (أو مدير الموارد البشرية بالإنابة) بتنفيذ النقل:

```javascript
// مثال: نقل ملكية هدف استراتيجي
PATCH /api/strategic-goals/[id]
Body: { 
  ownerUserId: [new_user_id],
  notes: "نُقلت الملكية من [قديم] إلى [جديد] بموجب القرار رقم..."
}
```

كل عملية نقل تُسجَّل تلقائياً في **سجل التدقيق (Audit Log)** بـ:
- المستخدم القديم والجديد
- الوقت والتاريخ
- المُنفِّذ للنقل

### خطوة 4️⃣ — التحقق

يُشغَّل فحص سلامة البيانات للتأكد من اكتمال النقل:

```bash
node apps/api/scripts/check-data-integrity.mjs
```

الفحص الرقم 13 (`USER-OWNERSHIP-001`) يكشف أي ملكيات معلَّقة لمستخدمين غير نشطين.

### خطوة 5️⃣ — تعطيل الحساب (لا حذف)

بعد نقل جميع الملكيات:

```javascript
PATCH /api/users/[id]
Body: { isActive: false }
```

**لا يُحذف المستخدم نهائياً** — يبقى السجل للأغراض التاريخية والتدقيق.

## 5. المسؤوليات

| الدور | المسؤولية |
|----|---------|
| **مدير الموارد البشرية** | إعلام مدير الجودة بأي مغادرة قبل 14 يوم من تاريخها |
| **مدير الجودة** | تنفيذ نقل الملكيات وتوثيقها |
| **المدير التنفيذي** | اعتماد قرار النقل |
| **الموظف المغادر** | تسليم سجل ملكياته كاملاً |
| **الموظف البديل** | إقرار باستلام المسؤوليات |

---

## 6. حالات الاستثناء

### حالة 1: مغادرة فورية بدون إشعار
- يتولّى المدير التنفيذي ملكية مؤقتة لجميع السجلات
- يُعيَّن البديل خلال 7 أيام
- تُنقل الملكيات للبديل فور تعيينه

### حالة 2: عدم وجود بديل مناسب
- تُسنَد للمدير التنفيذي مؤقتاً
- تُسجَّل ملاحظة "بديل مؤقت — يحتاج تعيين"
- مراجعة دورية كل 30 يوم

### حالة 3: مغادرة عضو مجلس إدارة
- يُتبَع نظام مجلس الإدارة المعتمد
- لا تُغيَّر ملكيات إلا بقرار المجلس

---

## 7. المراجعة الدورية

في كل **مراجعة إدارية ربعية**:

- يُقدَّم تقرير "ملكيات الموظفين النشطين"
- يُكشف أي خلل في التوازن (موظف يحمل عدداً غير منطقي)
- تُحدَّث الملكيات بناءً على التغييرات الوظيفية

---

## 8. الفحص الوقائي الآلي

النظام يُجري فحصاً آلياً يُكشف:

✅ مستخدمون غير نشطين لديهم سجلات حية (USER-OWNERSHIP-001)  
✅ سجلات بمالكين محذوفين  
✅ موظفون يحملون عبئاً غير متوازن (>10 سجلات)  

ينُتج تقريراً ربعياً يُعرض على مدير الجودة.
