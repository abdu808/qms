# دليل تنفيذ الخطة الاستراتيجية 2026-2030 داخل النظام

## الغرض

هذا الدليل يشرح طريقة تطبيق الهيكل الاستراتيجي المعتمد داخل نظام الجودة بدون حذف البيانات القديمة أو تغييرها صامتاً. التنفيذ مبني على سكربت آمن يعمل افتراضياً بوضع المعاينة فقط.

## نطاق التنفيذ

السكربت ينشئ أو يحدّث العناصر التالية:

- الخطة الاستراتيجية 2026-2030 برمز `PLAN-2026-2030`.
- أربعة محاور استراتيجية بعد دمج الحوكمة داخل التميز المؤسسي.
- عشرة أهداف استراتيجية مرتبطة بالمحاور والجهات المالكة.
- ثلاثون هدفاً تشغيلياً قابلاً للقياس.
- ثلاثون مؤشراً تشغيلياً واستراتيجياً مع مالك أداء ومالك بيانات.
- مستهدفات سنوية من 2026 إلى 2030 لكل مؤشر.
- أهداف فصلية تشغيلية تساعد على المتابعة الدورية.
- عشر مبادرات رئيسية مرتبطة بالأهداف الاستراتيجية.
- حسابات تنظيمية خاملة للمالكين المؤسسيين عند الحاجة.

## المحاور المعتمدة

| المحور | الوزن | الملاحظات |
|---|---:|---|
| الأثر الاجتماعي والمستفيدون | 35% | يشمل الخدمة المجتمعية والكفالات والتمكين. |
| الاستدامة المالية وتنمية الموارد | 25% | يفصل بين تنمية الموارد والمالية والاستثمار. |
| التميز المؤسسي والجودة والتحول الرقمي | 25% | يشمل الحوكمة والجودة وISO والمخاطر والتقنية. |
| رأس المال البشري والشراكات | 15% | يشمل الموارد البشرية والشراكات والتطوع. |

## أوامر التشغيل

تُنفذ الأوامر من مجلد `apps/api`.

### 1. المعاينة قبل التنفيذ

```bash
npm run plan2030:dry-run
```

هذا الأمر لا يكتب أي بيانات. يعرض ما سيتم إنشاؤه، وما هو موجود حالياً، وهل توجد بيانات قديمة تحتاج أرشفة.

### 2. التنفيذ بدون أرشفة القديم

### 2. اختبار التنفيذ الكامل مع التراجع

```bash
npm run plan2030:rollback-test
```

هذا الأمر ينفذ مسارات الإنشاء والتحديث كاملة داخل Transaction ثم يتراجع عنها عمداً. فائدته أنه يكشف أخطاء العلاقات والحقول الفعلية بدون ترك أثر في قاعدة البيانات.

### 3. التنفيذ بدون أرشفة القديم

```bash
npm run plan2030:apply
```

هذا الأمر ينشئ الخطة الجديدة ويترك السجلات القديمة كما هي. يستخدم عندما نريد مقارنة القديم بالجديد قبل التحويل الكامل.

### 4. التنفيذ مع أرشفة القديم

```bash
npm run plan2030:apply:archive
```

هذا الأمر ينشئ الخطة الجديدة ثم يؤرشف السجلات الاستراتيجية القديمة Soft Archive. لا يحذف البيانات نهائياً.

## خيارات متقدمة للمطور

| الخيار | المعنى |
|---|---|
| `--apply` | يسمح بالكتابة الفعلية في قاعدة البيانات. |
| `--dry-run` | معاينة فقط بدون كتابة. |
| `--archive-legacy` | أرشفة السجلات الاستراتيجية القديمة بدلاً من تركها نشطة. |
| `--skip-role-users` | عدم إنشاء حسابات تنظيمية للمالكين. |
| `--activate-role-users` | إنشاء حسابات المالكين التنظيميين كحسابات نشطة. لا يُنصح به قبل مراجعة الصلاحيات. |

## قواعد السلامة

- الوضع الافتراضي Dry Run ولا يكتب شيئاً.
- لا يوجد حذف نهائي لأي سجل.
- الأرشفة تتم عبر `deletedAt` أو حالة مناسبة مثل `CANCELLED`/`ARCHIVED`.
- الحسابات التنظيمية تنشأ خاملة افتراضياً حتى لا تتحول إلى مستخدمين فعليين.
- يتم إنشاء نسخة استراتيجية جديدة في `StrategicPlanVersion` عند كل تشغيل فعلي.

## ما يجب فحصه بعد التنفيذ

- عدد المحاور النشطة للخطة الجديدة = 4.
- عدد الأهداف الاستراتيجية للخطة الجديدة = 10.
- عدد الأهداف التشغيلية للخطة الجديدة = 30.
- عدد المؤشرات للخطة الجديدة = 30.
- عدد مستهدفات السنوات = 150.
- عدد المبادرات الرئيسية = 10.
- لا يوجد مؤشر بلا مالك أداء أو مالك بيانات.
- لا توجد مؤشرات تقنية مملوكة للخدمة المجتمعية أو الكفالات.
- لا توجد مؤشرات مستفيدين مملوكة للمستودع أو المالية.

## قرار الاعتماد المقترح

الترتيب الأفضل للتطبيق على الإنتاج:

1. أخذ نسخة احتياطية من قاعدة البيانات.
2. تشغيل `npm run plan2030:dry-run`.
3. تشغيل `npm run plan2030:rollback-test`.
4. مراجعة تقرير المعاينة والاختبار.
5. تشغيل `npm run plan2030:apply`.
6. مراجعة الخطة الجديدة داخل الواجهة.
7. بعد الاعتماد النهائي، تشغيل `npm run plan2030:apply:archive` إذا تقرر إخفاء القديم من التشغيل اليومي.
