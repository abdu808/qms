# خطة تجهيز محتوى ISO9001 وربطه بالنظام

**التاريخ:** 2026-05-02  
**النطاق:** مطابقة مجلد `ISO9001` مع API النظام الحي.

## 1. الخلاصة

تمت قراءة مجلد `ISO9001` ومقارنته بما ظهر عبر API الحي.

| المؤشر | النتيجة |
|---|---:|
| عناصر ISO9001 المحللة بعد استبعاد ملفات Word المؤقتة | 92 |
| وثائق ظاهرة في `GET /api/documents` | 0 |
| سياسات جودة ظاهرة في `GET /api/quality-policy` | 1 |
| مرشحات وثائق داخلية بعد إزالة التكرارات | 84 |
| ملفات مجهزة للموقع الرسمي | 9 |
| عناصر محلية غير ظاهرة كوحدة وثائق في API | 89 |
| عناصر مطابقة كسجل سياسة جودة فقط | 3 |

الاستنتاج: المستندات موجودة فعليًا في المشروع، لكن أغلبها غير ظاهر في النظام الحي كوحدة وثائق منشورة أو كأدلة مرتبطة ببنود ISO.

## 2. التصحيح المهم في القراءة

بعض البنود التي بدت “ناقصة” من API ليست ناقصة كمحتوى، بل ناقصة كربط أو كسجل تشغيلي.

مثال:

- المؤشرات لها مالك `ownerId`.
- الناقص هو مسؤول إدخال القراءة `dataEntryUserId` ومعتمد القراءة `approverUserId`.

لذلك سأتعامل مع كل بند بهذه الحالات:

| الحالة | المعنى |
|---|---|
| موجود كمستند | موجود في `ISO9001` أو ملفات المشروع |
| موجود كسجل نظامي | ظاهر في API كموديل/سجل |
| موجود لكن غير مكتمل | له سجل لكن يحتاج حقول تشغيلية |
| غير موجود تشغيليًا | لا يوجد سجل تنفيذ أو دليل حي |

### ب. عناصر لا يكفي رفعها كوثائق فقط

هذه تحتاج سجلات تنفيذ داخل النظام، لا مجرد مستند:

| المجال | الموجود | المطلوب داخل النظام |
|---|---|---|
| التدقيق الداخلي | IA-001 و IA-002 | إنشاء Audit فعلي + نتائج + إجراءات |
| مراجعة الإدارة | MR-001 و MR-002 | إنشاء Management Review مكتملة |
| عدم المطابقة | CA-001 و CA-002 | إنشاء NCR/CAPA عند وجود فجوات |
| المخاطر | QP-003 وسجل مخاطر API | اعتماد المخاطر وخروجها من DRAFT |
| التدريب والكفاءة | HR-001 ومواد تدريب | Competence + Training records |
| التواصل | توجد مواد/خطط مساندة | Communication Plan كسجل نظامي |
| رضا المستفيدين | QS-004 ومواد تقييم | Survey/Complaints evidence |
| الموردون | PUR-001 ونماذج تقييم | Supplier records + evaluations |

## 4. مسار العمل المقترح

### المرحلة 1: تثبيت الأدلة الوثائقية

1. إعداد قائمة الوثائق الأساسية من ملف المطابقة.
2. إزالة التكرارات بين مجلد `01_السياسات_والأهداف` و`05_وثائق_النشر_العام`.
3. تحديد لكل وثيقة:
   - الكود
   - العنوان
   - الإصدار
   - بند ISO
   - المالك
   - هل هي داخلية أم عامة
4. تسجيلها في وحدة الوثائق.
5. تجهيز الوثائق العامة المناسبة للنشر في الموقع الرسمي للجمعية، وليس عبر بوابة النظام العامة.

### المرحلة 2: إنشاء سجلات ISO التشغيلية

1. إنشاء تدقيق داخلي واحد على الأقل.
2. تسجيل نتائج التدقيق.
3. تحويل النتائج إلى NCR/CAPA عند الحاجة.
4. إنشاء مراجعة إدارة مكتملة.
5. اعتماد المخاطر العالية أولًا.
6. تسجيل خطة اتصال.
7. تسجيل مصفوفة كفاءات وخطة تدريب.

### المرحلة 3: إكمال حقول التخطيط والأداء

1. مراجعة الأهداف الاستراتيجية التي لا تحمل KPI/baseline/target على مستوى الهدف.
2. تعبئة `currentValue` للأهداف التشغيلية التي تحتاج قراءة أولية.
3. تعيين `dataEntryUserId` و`approverUserId` لكل مؤشر، مع بقاء `ownerId` كمالك للمؤشر.
4. استكمال المبادرات التي لا تحتوي إدارة أو تواريخ.

## 6. قرار مطلوب قبل الإدخال الفعلي

قبل أي إدخال أو رفع فعلي إلى النظام الحي، نحتاج اعتماد القاعدة التالية:

| نوع المحتوى | طريقة التعامل |
|---|---|
| وثائق السياسات والإجراءات | تسجل في وحدة الوثائق مع إصدار واعتماد |
| السياسات العامة | تسجل داخليًا في وحدة الوثائق، وتجهز نسخة للنشر في الموقع الرسمي للجمعية |
| خطط التدقيق والمراجعة | تستخدم لإنشاء سجلات تشغيلية، لا تكتفى كملفات |
| النماذج | تحفظ كقوالب أو وثائق مرجعية |
| الأدلة التدريبية | تحفظ كمواد تدريب/وثائق مساندة |

لا أنصح بعمل رفع جماعي مباشر قبل مراجعة جدول المطابقة؛ لأن بعض الملفات مكررة أو موجهة للنشر العام عبر الموقع الرسمي، وبعضها يجب أن يتحول إلى سجل تشغيلي بدل أن يبقى وثيقة فقط.

تم تجهيز سكربت تنفيذ آمن يعمل بنمط `dry-run` افتراضيًا. خطة الدفعة الأولى تحتوي 18 وثيقة أساسية ستنشأ كمسودات `DRAFT` في وحدة الوثائق، مع رفع ملف الإصدار. لا ينفذ السكربت أي كتابة على الإنتاج إلا عند تمرير خيارين صريحين:

```bash
node scripts/import-iso9001-documents.mjs --apply --yes-i-understand-production-write
```

ويجب توفير بيانات الدخول عبر متغيرات البيئة `QMS_EMAIL` و`QMS_PASSWORD` ويفضل تحديد `QMS_BASE_URL`.

## 7. قرار النشر العام

تم استبعاد بوابة النظام العامة من نطاق النشر. التوجيه المعتمد:

- النظام يستخدم لإدارة الوثائق، الاعتمادات، السجلات، والأدلة الداخلية.
- الموقع الرسمي للجمعية هو قناة النشر العام للسياسات والوثائق الموجهة للجمهور.
- لا توجد توصية بتفعيل `portalEnabled`.
- ملفات مجلد `05_وثائق_النشر_العام` تعامل كحزمة محتوى للموقع الرسمي، مع الاحتفاظ بنسخة داخل النظام لأغراض الضبط والإصدار.
